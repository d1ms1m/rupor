# Оболочка Рупора (Tauri 2, Rust)

Окна `main` и `pill`, значок в трее и супервизор Python-ядра. Контракты — в
[docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md) (разделы «Процессы» и «Tauri (Rust)»);
здесь — как собрать и отладить, плюс расширения контракта.

## Сборка и проверка

```sh
export PATH="$HOME/.cargo/bin:$PATH"
cd ui/src-tauri
cargo build            # debug: окна грузят http://localhost:1420 (npm run dev)
cargo test             # юнит-тесты + тест супервизора с поддельным ядром (tests/fake_core.py)
cargo test -- --ignored real_core_smoke   # настоящее ядро из .venv: --sidecar --no-hook --no-mutex
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

`cargo build` в debug не требует собранного фронтенда (`ui/dist`): окна грузят dev-сервер.

Установщик собирает `build.cmd` в корне проекта: PyInstaller-ядро → `resources/core/` →
`npm run tauri build` → `target/release/bundle/nsis/Рупор_<версия>_x64-setup.exe`
(установка для текущего пользователя в `%LOCALAPPDATA%\Рупор`). Установщик двуязычный:
`bundle.windows.nsis.languages` — `["English", "Russian"]`, при запуске окно выбора языка
(`displayLanguageSelector`), по умолчанию — язык Windows, для прочих языков — английский;
выбор запоминается в реестре, деинсталлятор говорит на нём же. `productName` остаётся
«Рупор»: от него зависят папка установки, ключи реестра и автозапуск прежних установок.
Название на языке установщика показывают хуки (см. ниже): заголовок и страницы мастера и
деинсталлятора, сообщение «… запущен», DisplayName и Publisher в «Установленных
приложениях». Из `${PRODUCTNAME}` при компиляции собраны и остаются «Рупор»: имя файла
установщика и его свойства (VIAddVersionKey), папка, ярлыки, тексты шаблона о
переустановке (`alreadyInstalledLong`, `uninstallApp`…); FileDescription самого `rupor.exe`
(диспетчер задач, «Автозагрузка», значки в области уведомлений) — тоже productName.
Свой шаблон NSIS (`bundle.windows.nsis.template`) убрал бы и их, но это копия шаблона Tauri,
которую пришлось бы сверять с каждым обновлением `@tauri-apps/cli`.
Release-сборка без `resources/core/rupor-core.exe` падает в `build.rs` с подсказкой
(иначе получился бы установщик без ядра); если ядро действительно не нужно (проверка
сборки оболочки) — `RUPOR_ALLOW_NO_CORE=1`. В debug `build.rs` создаёт пустую
`resources/core/` с `README.txt`, чтобы tauri-build не падал на отсутствующем ресурсе.
`build.rs` сверяет версию из `Cargo.toml` с `tauri.conf.json`, `ui/package.json` и
`pyproject.toml`: в release расхождение — ошибка, в debug — предупреждение. Каждую
раздаваемую сборку выпускайте с новой версией во всех четырёх файлах.

Хуки установщика — `windows/hooks.nsh` (`bundle.windows.nsis.installerHooks`):
- `LangString ^Name` / `^NameDA` на обоих языках — название в заголовке и на страницах
  мастера («Rupor Setup», «Welcome to Rupor Setup»); шаблон ставит `Name "${PRODUCTNAME}"`
  позже, но строка языка, заданная раньше атрибута `Name`, для этого языка главнее
  (makensis 3.11);
- после установки DisplayName и Publisher в ключе удаления переписываются на название на
  языке установщика; сами ключи `Software\Рупор` и `…\Uninstall\Рупор` прежние;
- перед установкой и удалением — проверка «Рупор запущен» с именем на языке установщика;
- перед установкой прежняя папка `core\` удаляется целиком — от старой сборки ядра не
  остаются лишние файлы (`av.libs\*-<хэш>.dll`, чужие `*.dist-info`); после удаления
  программы остатки `core\` тоже снимаются;
- галочка «Удалить данные приложения» (кроме режима обновления) удаляет ещё
  `%APPDATA%\Rupor` (настройки, история, журналы), `%LOCALAPPDATA%\Rupor` (CUDA) и ключи
  `Rupor/openrouter`, `Rupor/anthropic` из диспетчера учётных данных. Без галочки данные
  остаются: деинсталлятор старой версии запускается и при установке новой поверх.
  Модель в общем кэше HuggingFace не удаляется.

Сообщения хуков (`DetailPrint`, имя программы в «… запущен») — `LangString` на обоих языках
установщика. Хуки подключаются раньше `MUI_LANGUAGE`, поэтому языки в них заданы кодами
LANGID (1033, 1049), а не `${LANG_ENGLISH}` / `${LANG_RUSSIAN}`. Новое сообщение — две строки
`LangString`, иначе makensis предупредит о строке без перевода. Проверить скрипт без сборки
установщика: скопировать `target/release/nsis/x64/installer.nsi` после `tauri build` и
собрать `%LOCALAPPDATA%\tauri\NSIS\Bin\makensis.exe -V3 installer.nsi` (0 предупреждений,
«2 language tables»).

Иконки: `scripts/make_icons.py` рисует `icons/app-icon.png` (1024×1024) и `icons/tray/*.png`
(32×32 по состояниям), затем `npx --yes @tauri-apps/cli@2 icon icons/app-icon.png -o icons`.

## Откуда берётся ядро

1. `RUPOR_CORE` — полная командная строка (для отладки; кавычки для путей с пробелами);
2. `<папка программы>\core\rupor-core.exe` — установленная версия;
3. только debug-сборка: `.venv\Scripts\python.exe -m rupor` с рабочей папкой `core\`.

`RUPOR_CORE_ARGS` — дополнительные аргументы ядра, например `--no-hook --no-mutex -v`
(без хука клавиатуры — тестовое ядро не перехватывает хоткеи).

Ядро запускается без окна (`CREATE_NO_WINDOW`), в job object с `KILL_ON_JOB_CLOSE`
(умирает вместе с оболочкой). Упало не по «Выходу» — перезапуск через 1 / 3 / 10 с,
счётчик сбрасывается после 60 с работы, в окна уходит `core-restarted`.

Расширение контракта — ядро, которое завершается, не успев открыть порт:
- мьютекс ядра `Local\RuporSingleInstance` занят (работает другой Рупор, например старая
  версия из автозагрузки; с `--no-mutex` не проверяется) — трей «уже запущен другой Рупор»,
  ядро не перезапускается, пока тот не закроется (проверка раз в 2 с);
- иначе после 3 таких выходов подряд — трей «ядро не запускается» и попытка раз в минуту.

Причина уходит в ошибку `backend_info`: «уже запущен другой Рупор…» или код выхода плюс
последняя строка ERROR/CRITICAL, которую ядро дописало в `%APPDATA%\Rupor\logs\rupor.log`
за этот запуск.

Журнал оболочки — `%APPDATA%\Rupor\logs\ui.log` (токен ядра туда не пишется).

## Команды (`invoke`) и события

| Команда | Аргументы | Результат |
|---|---|---|
| `backend_info` | — | `{port, token}`; ждёт готовности ядра до 30 с, иначе ошибка-строка |
| `update_tray` | `{state, paused, insert_mode?, style?, styles?: [{id, name}], ai_line?: string \| null, rdp?: [{key, title, included}] \| null, labels?: {lang?, app?, status_*?, pause?, …} \| null}` | — (подробнее ниже) |
| `relaunch_admin` | — | UAC → новый экземпляр с `--elevated --wait-pid <pid>`, этот выходит; отказ в UAC — ошибка (подробнее ниже) |
| `show_main` | `{route?}` | показать/развернуть/активировать главное окно, с `route` — событие `navigate` |
| `quit_app` | — | остановить ядро и выйти |
| `set_pill_passthrough` | `{on}` | клики сквозь пилюлю |
| `reset_pill_position` | — | пилюля — вниз по центру основного монитора (`pill_position: null` фронтенд сохраняет сам) |

Аргументы — в snake_case, как в контракте (`insert_mode`, не `insertMode`).

События (во все окна): `tray-action {id}` — `pause`, `mode:auto|type|clipboard`,
`style:<id>`, `last_insert`, `rdp:<key>` (обрабатывать только в `main`); `core-restarted {}`;
`navigate {route}`.

Меню трея: статус (неактивный), строка расхода ИИ (неактивная, есть только при `ai_line`),
—, Пауза, Режим вставки ▸, Стиль ▸, Рассылка в RDP ▸ (есть только при `rdp`), Вставить
последнее, —, Открыть Рупор, Выход.

`update_tray`, поля `ai_line` и `rdp`: ключа нет — пункт остаётся как был (вызов только со
сменой состояния ничего не прячет); `null` — пункт убирается; значение — показывается.
- `ai_line` — текст неактивной строки, например «ИИ: сегодня $0.03 · баланс $12.34»;
  пустая строка — как `null`. При том же тексте меню не трогается.
- `rdp` — подменю «Рассылка в RDP» с флажками (`included`); подпись — `key` (имя сервера
  mstsc или заголовок окна прочих клиентов), до 60 символов; повторы `key` без учёта
  регистра отбрасываются, пустые `key` пропускаются; `[]` — неактивный пункт «Нет открытых
  RDP-сессий». Пункты пересоздаются только при смене набора сессий, смена флажков — на месте.
  Клик по сессии → `tray-action {id: "rdp:<key>"}` с `key` как пришёл; галочку оболочка
  возвращает в прежнее состояние, новое приходит следующим `update_tray` (после `rdp_toggle`
  к ядру). Ключ сессии в `ui.log` не пишется.

Команда разбирает тело `invoke` целиком (`tauri::ipc::Request`): аргументы-`Option` не
отличают отсутствующий ключ от `null`. Тело — только объект JSON.

`update_tray.labels` — подписи трея на языке интерфейса (`tray::TrayLabels`): ключа нет —
прежние подписи, `null` — встроенные на текущем языке оболочки, объект — встроенные на языке
`lang`, поверх — присланные. Любой ключ можно не присылать (нет, `null` или пустая строка —
встроенная подпись), незнакомые ключи пропускаются, значение — только строка (иначе ошибка
разбора всего вызова). Управляющие символы убираются, `&` в меню экранируется.

| Ключ | Где | ru (встроенная) | en (встроенная) |
|---|---|---|---|
| `lang` | язык подписей и сообщений оболочки: `ru` \| `en` (`State.ui_language`); другое — язык не меняется | | |
| `app` | «`app`: статус» в меню, «`app` — статус» в подсказке | Рупор | Rupor |
| `status_loading`, `status_idle`, `status_recording`, `status_hands_free`, `status_processing`, `status_ai`, `status_paused`, `status_error` | статус по `State.state` (`paused` — `status_paused`) | загрузка модели…, готов, … | Loading model…, Ready, … |
| `status_starting`, `status_restarting`, `status_failed`, `status_already_running` | статусы, которые ставит оболочка (ядро запускается / перезапускается / не запускается / мешает другой Рупор) | запуск ядра…, … | Starting engine…, … |
| `pause`, `insert_mode`, `mode_auto`, `mode_type`, `mode_clipboard`, `style`, `rdp`, `rdp_empty`, `last_insert`, `open`, `quit` | пункты меню (`rdp_empty` — заглушка «Нет открытых RDP-сессий») | Пауза, Режим вставки, … | Pause, Insert method, … |

Полный список встроенных строк — `src/i18n.rs` (`RU.tray`, `EN.tray`). Меню при смене
подписей не перестраивается: новый текст получают только изменившиеся пункты, при тех же
подписях меню не трогается; строка статуса и подсказка обновляются, только если изменились.
Названия стилей в трее — из `styles` (их локализует ядро в `styles_list`); пока интерфейс
их не прислал, в меню встроенные стили на языке оболочки, и они переподписываются при смене
`lang`.

## Язык оболочки

Язык трея до первого `update_tray.labels`, заголовков окон по умолчанию и сообщений самой
оболочки — `src/i18n.rs`:
- при запуске — `language` из `settings.json` (ровно `ru` | `en`); для `system`, без ключа
  и для неверного значения (в том числе `EN`, ` en ` — ядро их тоже не принимает и берёт
  `system`) — язык интерфейса Windows (`GetUserDefaultUILanguage`): русский для
  ru/be/uk/kk, иначе английский, как у ядра;
- потом — `update_tray.labels.lang` от интерфейса, на лету.

На этом языке: подписи трея по умолчанию, заголовки окон при запуске («Рупор» / «Rupor»,
пилюля — «Рупор — пилюля» / «Rupor — indicator»; дальше заголовки ставит интерфейс `setTitle`,
права есть у обоих окон), ошибки `backend_info`, `relaunch_admin`, `reset_pill_position`,
`set_pill_passthrough`, окно «не удалось запустить» (WebView2). Ошибки разбора аргументов
`update_tray` — для разработчика, по-русски; журнал `ui.log` — по-русски. Причина из
журнала ядра в ошибке `backend_info` приходит как её записало ядро.
Встроенные подписи трея и заголовок пилюли совпадают с `ui/src/i18n/<lang>.json`
(раскладка ключей — как в `App.tsx`), имена встроенных стилей — с
`core/rupor/locales/<lang>.json`; это проверяет тест
`i18n::tests::builtin_texts_match_ui_and_core` — иначе пункты меню заметно
переименовывались бы при первом `update_tray.labels`.

`relaunch_admin`: Windows показывает запрос UAC сразу, только если окно-владелец на переднем
плане (иначе лишь мигает кнопка на панели задач), а пилюля не активируется. Поэтому перед
запросом показывается и активируется главное окно, его HWND — владелец запроса; при отказе
окно снова прячется, если было скрыто. Повторный вызов, пока запрос открыт, — ошибка.
Параметры нового экземпляра: `--show-main` — главное окно было открыто, показать его;
`--core-cmd` / `--core-args` — значения `RUPOR_CORE` / `RUPOR_CORE_ARGS` (повышенный процесс
не наследует окружение; принимаются только вместе с `--elevated`).

## Пилюля и фокус

Пилюля никогда не активируется: `focus: false` + `focusable: false` в конфиге,
`WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` после создания и сабклассинг окна (стиль не
теряется, когда tao его переписывает; клики и перемещения — без активации; если окно
всё же активировали — активность сразу возвращается прежнему окну).
Позиция: `pill_position` из `settings.json`, если она на каком-нибудь мониторе, иначе —
снизу по центру рабочей области основного монитора.
